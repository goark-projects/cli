# 生命周期与任务图

[English](lifecycle-and-tasks.md) | 简体中文

## 为什么生命周期固定

Goark 将代码生成和声明的钩子视为构建契约的一部分。固定顺序可以避免本地运行、CI 构建和发布过程使用不同的生成源码或工具版本。增强命令不提供跳过生成的开关；需要原始 Go 行为时使用 `goark go ...`。

## 普通增强命令

`run`、`build`、`test`、`install`、`vet`、`list` 按以下顺序执行：

```text
加载 go.mod 和严格 goark.build
选择 --goark-profile
合并命令、Profile、CLI 和环境值
校验任务 DAG 与项目路径
解析并验证需要的锁定工具
获取跨进程项目锁
  commands.generate.before
  Goark 内置代码生成
  commands.generate.after
  commands.generate.finally
  commands.<当前命令>.before
  官方 Go 命令
  commands.<当前命令>.after，仅成功后
  commands.<当前命令>.finally，始终执行
释放项目锁
```

当前实现会在完整生命周期内持有项目锁，防止任务、生成输出、官方命令和收尾过程观察到同一项目中另一个 Goark 生命周期的并发修改。

## `generate`

`goark generate` 只执行：

```text
commands.generate.before
Goark 内置代码生成
commands.generate.after，仅成功后
commands.generate.finally，始终执行
```

它不会调用 `go generate`。标准 Go directive 应使用 `goark go generate ./...`。

## `fix`

`goark fix` 的顺序不同：

```text
commands.fix.before
go fix
完整 generate 生命周期
commands.fix.after，仅成功后
commands.fix.finally，始终执行
```

这样可以基于 `go fix` 修改后的源码重新生成。

## 钩子失败规则

- `before`、内置生成或官方 Go 命令失败后，不执行 `after`。
- 即使发生取消或前序失败，也始终执行 `finally`。
- `finally` 按反向依赖顺序执行，单个 finalizer 失败后继续处理其他 finalizer。
- 已存在主流程失败时保留其退出码；只有主流程成功时，`finally` 失败才成为最终结果。
- 操作系统允许时原样保留子进程退出码；取消对应退出码 130。

## 任务 DAG

每个 `[tasks.<name>]` 是一个节点，`depends-on` 指向上游节点：

```toml
[tasks.assets]
type = "go"
args = ["run", "./cmd/assets"]
outputs = ["internal/assets/assets_gen.go"]

[tasks.package]
type = "group"
depends-on = ["assets", "metadata"]
```

执行前校验：

- 每个目标和依赖都存在。
- 同一任务不能重复声明同一个依赖。
- 任务图不存在循环。
- 不同任务的声明输出不能重叠。
- 工作目录、输入、输出和本地工具在解析符号链接后仍位于规范化项目根目录内。
- 每个 `exec` 任务都引用已声明工具。

## 任务类型

### `exec`

使用“可执行文件 + 参数数组”运行声明工具：

```toml
[tools.formatter]
type = "system"
command = "gofmt"
install = "manual"

[tasks.format]
type = "exec"
tool = "formatter"
args = ["-w", "./internal"]
```

执行过程不经过 Shell，因此不会解释管道、重定向、`&&`、命令替换和 Shell 内置命令。

### `go`

使用受控参数执行官方 Go：

```toml
[tasks.verify-modules]
type = "go"
args = ["mod", "verify"]
```

### `delete`

只删除声明的项目内输出匹配项：

```toml
[tasks.clean-assets]
type = "delete"
outputs = ["internal/assets/*_gen.go"]
```

禁止删除项目根目录，符号链接目标会重新校验。删除任务不能启用缓存。

### `group`

聚合一个或多个依赖，不启动进程：

```toml
[tasks.verify]
type = "group"
depends-on = ["unit-test", "static-check"]
```

`goark-generate` 是 CLI 内部节点，不能在 `goark.build` 声明。

## 并发

调度器使用 `execution.max-parallel` 作为上限。就绪任务只有显式声明 `parallel-safe = true` 才能并发，未声明时默认串行。静态输出冲突检查会拒绝输出路径或 glob 前缀可能重叠的任务。

```toml
[execution]
max-parallel = 4

[tasks.unit]
type = "go"
args = ["test", "./internal/unit/..."]
parallel-safe = true

[tasks.integration]
type = "go"
args = ["test", "./internal/integration/..."]
parallel-safe = true
```

只有工具、工作目录、环境和未声明副作用也支持并发时，才能设置 `parallel-safe = true`。输出不相交不能单独证明外部进程安全。

`fail-fast = true` 时，首个失败会取消剩余任务；设为 `false` 时，独立的就绪任务可以继续完成，但执行器最终仍返回失败。

## 条件

任务启动前计算 `when`：

```toml
when = 'profile == "production" && goos == "linux" && env.CI == "true"'
```

跳过任务在依赖调度中视为成功，并向下游缓存指纹提供稳定的 `skipped` 上游状态。

## 生成文件所有权

项目生成文件名为 `zz_goark_<package>_gen.go`。每次生成都会重建完整内容，并原子替换已有的 Goark 所有目标。所有权标头为：

```go
// Code generated by goark; DO NOT EDIT.
```

Goark 拒绝覆盖同名手写文件。`clean-stale = true` 时只删除带有上述精确标头的过期文件。dry-run 只报告变化，不创建、不替换、不删除文件。

## 信号与标准流

任务和 Go 子进程继承标准输入、输出和错误。中断和终止取消会传递到整个生命周期；进程运行器使用平台相关方式终止子进程树。生成的 Web 应用也会把进程信号转换为 Boot 关闭，并使用有时限的 context 完成关闭。
