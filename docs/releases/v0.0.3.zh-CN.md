# Goark CLI 0.0.3

[English](https://github.com/goark-projects/cli/blob/v0.0.3/docs/releases/v0.0.3.md) | 中文

发布日期：2026 年 9 月 7 日

Goark CLI 0.0.3 精简 App、Web 骨架，修复依赖解析及参数边界问题。
公开命令名称与 `goark.build` V1 模式保持不变。

## :lady_beetle: 问题修复

- 增强 Go 工作流在允许写入时补齐模块依赖和校验和，保留显式参数、持久化 `GOFLAGS`、
  工作区及 vendor 模式。
- 在选择注解源文件前应用命令最终环境配置。
- `-args`、`--` 后的测试业务参数不再影响项目发现、模块模式、生成参数及工具缓存标签；
  参数值不会被重新解释为选项。
- 拒绝重复应用注解，并将启动失败信息输出到标准错误。

## :package: 注解式应用

- 通过 `//goark:application` 和 `//goark:configuration` 生成应用启动代码。
- 使用注解式 Service、接口注入和 Web Controller，替代手工装配。
- 保持 `main.go` 精简，启动代码生成到 `internal/app/gen/zz_goark_application_gen.go`。
- `resource/app.yml` 仅保留应用名称；日志与出站 HTTP 客户端默认配置无需显式声明。

## :information_source: 升级说明

- CLI 模块最低要求 Go 1.26，新生成的 App、Web 项目最低要求 Go 1.27。
- 不会自动改写既有项目。应显式迁移手工启动装配，不要将 `goark new -force` 覆盖业务代码
  作为升级操作。
- 新项目可以直接 `goark run`；使用原生 Go 工具时，应先 `goark generate`，再执行
  `go mod tidy`，确保生成包已经存在。
- App 是执行后退出的一次性应用；需要常驻 HTTP 服务时使用 `goark new -type web <name>`。
  服务端配置覆盖键为 `server.address`、`server.port`。
- 只读模块模式会报告缺失依赖，不改写 `go.mod`、`go.sum`；确需更新依赖时再显式启用写模式。

## :white_check_mark: 验证

- Windows、Debian 全量测试、竞态检测、vet、静态分析及模块校验通过。
- 漏洞扫描未发现已知漏洞；参数模糊测试通过。
- 公共模块 App、Web 生成与编译通过。
- Debian Web 健康检查、端口冲突诊断及 SIGTERM 优雅退出通过。
- 发布流水线在生成六种架构归档前验证 Windows、Linux、macOS。

发布后安装：

```bash
go install goark.dev/cli/cmd/goark@v0.0.3
goark version
```

预期输出：`goark 0.0.3`。
