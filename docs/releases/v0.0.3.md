# Goark CLI 0.0.3

English | [中文](https://github.com/goark-projects/cli/blob/v0.0.3/docs/releases/v0.0.3.zh-CN.md)

Release date: September 7, 2026

Goark CLI 0.0.3 simplifies App and Web scaffolds and fixes dependency resolution and argument
boundaries. Public command names and the `goark.build` V1 schema remain unchanged.

## :lady_beetle: Bug Fixes

- Complete missing module requirements and checksums during enhanced Go workflows when writable
  module mode is allowed; preserve explicit flags, persisted `GOFLAGS`, workspaces, and vendor mode.
- Apply the configured command environment before selecting annotation source files.
- Keep test arguments after `-args` or `--` out of project discovery, module-mode selection,
  generation flags, and tool-cache tags. Preserve flag values without interpreting them as options.
- Reject duplicate application annotations and print startup failures to standard error.

## :package: Annotation-Based Applications

- Generate application startup through `//goark:application` and `//goark:configuration`.
- Use annotated services, interface injection, and Web controllers instead of handwritten wiring.
- Keep `main.go` small and emit startup code into `internal/app/gen/zz_goark_application_gen.go`.
- Reduce `resource/app.yml` to the application name; logging and outbound HTTP client defaults do
  not need explicit configuration.

## :information_source: Upgrade Notes

- The CLI module requires Go 1.26 or later. New App and Web projects require Go 1.27 or later.
- Existing projects are not rewritten automatically. Migrate handwritten startup wiring explicitly;
  do not overwrite application code with `goark new -force` as an upgrade procedure.
- New projects can start with `goark run`; when using standalone Go tooling, run `goark generate`
  before `go mod tidy` so generated imports exist.
- App projects are one-shot applications. Choose `goark new -type web <name>` for an HTTP server
  that remains running until interrupted. Server overrides use `server.address` and `server.port`.
- Read-only module mode intentionally reports missing dependencies without changing `go.mod` or
  `go.sum`. Use an explicit writable mode only when dependency updates are intended.

## :white_check_mark: Verification

- Windows and Debian full tests, race detection, vet, static analysis, and module checks pass.
- Vulnerability scanning reports no known vulnerabilities; parameter fuzz testing passes.
- Public-module App and Web generation and compilation pass.
- Web health checks, port-conflict diagnostics, and graceful SIGTERM shutdown pass on Debian.
- Release CI validates Windows, Linux, and macOS before publishing six architecture archives.

Install after publication:

```bash
go install goark.dev/cli/cmd/goark@v0.0.3
goark version
```

Expected output: `goark 0.0.3`.

Prebuilt archives are unsigned and include SHA-256 checksums in `checksums.txt`.
