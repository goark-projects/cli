# 代码生成

[English](code-generation.md) | 简体中文

## 两种入口

Goark 提供两个职责不同的生成入口：

| 命令 | 适用场景 |
| --- | --- |
| `goark generate` | 普通项目工作流：发现 package 并重新生成全部启用的 Goark 编译期代码。 |
| `goark codegen ...` | 低层工具：生成一个显式产物，或扫描一个 package 并手工选择输出。 |

两者都不会执行标准 `//go:generate` directive。需要该行为时使用 `goark go generate ...`。

## 项目级生成

```bash
goark generate
goark generate ./internal/...
goark generate -tags=integration ./...
goark generate --goark-profile=production
goark generate --goark-dry-run
```

package 集合默认来自 `[generate].patterns`，其默认值为 `./...`。发现使用官方 `go list` 的实际构建文件集，并遵守传入的 `-C`、`-tags`、`-mod`、`-modfile`、`-overlay`。

当前注解生成器覆盖 Goark 生成器包已支持的组件、服务、仓储、配置、Bean、注入点、条件、Profile、顺序、作用域、配置属性和 Web/MVC 声明注册元数据。

## 输出所有权

项目输出文件名为：

```text
zz_goark_<package>_gen.go
```

每次成功生成都会重建完整文件，并原子替换上一次所有目标。必需所有权行：

```go
// Code generated by goark; DO NOT EDIT.
```

它提供三项保护：

- 不会发布只写入一部分的截断目标。
- 成功重新生成后不会残留旧声明。
- 同名手写文件绝不会被静默覆盖。

`clean-stale = true` 时，如果 package 不再需要输出，只有该标头能证明 Goark 所有权时才删除旧文件。

## Dry Run

`--goark-dry-run` 执行发现和规划，但不创建、不替换、不删除源码，也不执行生命周期任务进程。

```bash
goark generate --goark-dry-run
```

## 低层 `annotations`

```text
goark codegen annotations --dir <package-dir> [flags]
```

| 参数 | 作用 |
| --- | --- |
| `--dir <path>` | package 目录，默认为当前目录。 |
| `--package <name>` | 一个目录包含多个 package 时选择名称。 |
| `--name <name>` | 没有显式 configuration 时使用的配置名。 |
| `--type <name>` | 没有显式 configuration 时使用的配置类型。 |
| `--output <path>` | 写入文件，不提供时输出到标准输出。 |

```bash
goark codegen annotations \
  --dir internal/app \
  --output internal/app/zz_goark_app_gen.go
```

## 低层 `configuration`

```text
goark codegen configuration --name <name> --package <package> [flags]
```

该命令生成一个 `goark.Configuration` 源文件。参数包括 `--type`、`--order`、可重复 `--import`、可重复 `--bean` 和 `--output`。

Bean 语法：

```text
name=provider[;deps=a,b][;scope=prototype][;lazy][;primary]
```

```bash
goark codegen configuration \
  --name user \
  --package generated \
  --bean "userRepository=NewUserRepository" \
  --bean "userService=NewUserService;deps=userRepository" \
  --output internal/generated/user_configuration.go
```

## 低层 `registry`

```text
goark codegen registry --package <package> --configuration <type> [flags]
```

该命令生成注册显式配置类型的函数。`--configuration`、`--import` 可重复，`--function` 修改函数名，`--output` 写入结果。

```bash
goark codegen registry \
  --package generated \
  --import cfg=example.com/app/internal/config \
  --configuration cfg.AdminConfiguration \
  --output internal/generated/registry.go
```

## 如何选择

- 开发、CI、`run`、`build`、`test` 生命周期使用 `goark generate`。
- 生成器开发、显式构建工具或通过标准输出检查结果时使用低层 `codegen`。
- 只有项目明确需要执行标准 Go directive，并接受其独立工具和副作用时，才使用 `goark go generate`。
