# Troubleshooting

English | [简体中文](troubleshooting.zh-CN.md)

## `goark.build` Not Found

Project-aware commands locate `go.mod` and require `goark.build` beside it. Run inside the intended module, use Go's `-C` where supported, or create the file next to `go.mod`. `goark go ...`, `new`, `codegen`, `help`, `version`, and `completion` do not require it.

## Unknown or Duplicate TOML Field

The parser is strict. Check spelling and table placement against the [`goark.build` reference](goark-build.md). Do not retain deprecated or speculative fields. A key may be declared only once.

## Encoding or Line-Ending Failure

`goark.build` and `goark.build.lock` require UTF-8 without BOM and LF-only line endings. Configure Git accordingly:

```gitattributes
*.build text eol=lf
*.lock text eol=lf
```

Do not convert these files to Windows CRLF.

## Multiple Main Packages

Set the intended default explicitly or pass a target:

```toml
[project]
main = "./cmd/server"
```

```bash
goark run ./cmd/worker
goark build ./cmd/server
```

## Lock Missing or Stale

After an intentional build or tool change:

```bash
goark sync
goark tool verify
```

Review and commit `goark.build.lock`. Do not manually edit the build digest or executable hash.

## Tool Is Missing

- Go tool with `install = "auto"`: run `goark sync` while online.
- Go tool with `install = "manual"`: run `goark tool install <name>`.
- System tool: install it with the OS package manager and place it on effective `PATH`.
- Local tool: build or restore the executable at the declared project path.

Use `goark tools --json` and `goark doctor` to distinguish `missing`, `unlocked`, and `drift`.

## Project Is Not Trusted

Automatic Go tool restoration is blocked until synchronization binds trust to the canonical root and current build digest:

```bash
goark sync
```

Moving the project or editing `goark.build` requires synchronization again.

## Offline Mode Fails

Offline execution cannot install or restore tools. Prepare while online with `goark sync` and `goark tool verify`, and ensure the Go module cache contains all dependencies. `--goark-offline` controls Goark tool installation; configure official Go separately, for example with `GOPROXY=off`, when the entire build must be network-isolated.

## Task Cycle or Missing Dependency

Dependencies must point upstream. Break cycles by extracting a shared prerequisite instead of making tasks depend on each other. After fixing names, inspect:

```bash
goark graph
goark graph --format=dot > tasks.dot
```

## Output Conflict

Each task must own a disjoint output set. Assign separate directories or exact files. A broad pattern such as `build/**` conflicts with nested outputs and should be owned by one task only.

## Cache Never Hits

Check that inputs are stable, every output pattern matches after success, output bytes and permissions remain unchanged, and all influential environment values are in `environment-inputs`. Profile, Go version, GOOS/GOARCH, build tags, tool lock, and upstream output changes also invalidate the key.

Use `goark clean --goark-dry-run` before deleting cache state.

## Generated File Is Not Overwritten

Goark only replaces targets carrying:

```go
// Code generated by goark; DO NOT EDIT.
```

A same-named handwritten file blocks generation by design. Rename it or intentionally replace it with a Goark-owned generated file. Never add the ownership header to human-maintained code.

## Standard `go generate` Did Not Run

This is expected. `goark generate` owns only Goark compile-time generation:

```bash
goark go generate ./...
```

## Profile Has No Runtime Effect

`--goark-profile` selects a build Profile only. Activate the Boot runtime Profile separately:

```bash
goark run --goark-profile=dev --goark.profiles.active=dev
```

or set `GOARK_PROFILES_ACTIVE=dev`.

## Diagnose Without Changes

```bash
goark info
goark info --json
goark tools --json
goark graph --format=json
goark build --goark-dry-run
```

`doctor` also leaves project state unchanged, but probes the installed Go executable.
