# Tools, Lock File, Trust, and Cache

English | [简体中文](tools-lock-cache.zh-CN.md)

## Tool Sources

Goark resolves external executables from explicit `goark.build` declarations. Tasks never contain a shell command string.

| Type | Declaration | Resolution | Installation |
| --- | --- | --- | --- |
| `go` | `package`, exact `version`, `install` | Isolated Goark user cache | Automatic only when allowed, or explicit with `tool install` |
| `system` | `command`, `install = "manual"` | Current effective `PATH` | Never |
| `local` | Project-relative `path`, `install = "manual"` | Canonical path inside project | Never |

Only a task reachable from the requested lifecycle needs to be resolved. Unused declared tools do not block a normal command unless `--goark-locked` requests complete declaration verification.

## Recommended Setup

After adding or changing a tool declaration:

```bash
goark sync
goark tool verify
git add goark.build goark.build.lock
```

Commit the lock file. Do not commit the user tool cache or local trust records.

## `goark sync`

### Normal Mode

```bash
goark sync
```

Normal synchronization:

1. Hashes the exact `goark.build` bytes.
2. Reads existing lock entries when present.
3. Resolves every declared tool for the current GOOS/GOARCH.
4. Auto-installs missing Go tools declared with `install = "auto"`.
5. Writes a normalized `goark.build.lock` atomically.
6. Records local trust for the canonical project root and build-file digest.

Entries for other platforms are retained while current-platform entries are replaced.

### Locked Mode

```bash
goark sync --locked
```

Locked mode is verification-only. It requires the existing lock to match the current build digest, declarations, platform entries, executable identities, and SHA-256 values. It neither installs tools nor updates the lock.

### Offline Mode

```bash
goark sync --offline
```

Offline mode forbids network access and installation. Every tool must already be locally resolvable. If resolution succeeds, `sync` may still update the lock and trust record. Use `sync --locked` when writes must also be prohibited.

## `goark.build.lock`

The lock file is strict TOML, UTF-8 without BOM, and LF-only. It is generated by Goark and should not be edited manually.

Top-level fields:

| Field | Meaning |
| --- | --- |
| `version` | Lock format version, currently `1`. |
| `build-sha256` | SHA-256 of the exact `goark.build` content. |
| `[[tools]]` | Stable, sorted platform-specific tool entries. |

Every tool entry records:

- `name`, `type`, `goos`, and `goarch`.
- A canonical logical or resolved `path`.
- Executable `sha256`.
- For Go tools: declared package/version plus module path, module version, and module checksum read from the executable build information.

Because the lock is platform-specific, teams should run `goark sync` on each supported OS/architecture and commit the merged result.

## Project Trust

Trust is local machine state, stored below the operating system's user configuration directory under `goark/trust`. A record binds:

- The canonical project root after symlink resolution.
- The exact `goark.build` SHA-256.

Trust is created by successful normal `sync` or explicit `tool install`. Editing `goark.build` invalidates the previous record until synchronization succeeds again.

During a lifecycle, Goark may restore a missing or drifted Go tool automatically only when all conditions are true:

- The tool is `type = "go"` and `install = "auto"`.
- The lock file is complete and matches the declaration and build digest.
- The project trust record matches the canonical root and digest.
- Neither dry-run nor offline mode is active.
- The restored executable exactly matches the locked metadata and digest.

System and local tools are never restored.

## Tool Status

```bash
goark tools
goark tools --json
```

| Status | Meaning |
| --- | --- |
| `ready` | Tool resolves and matches its current-platform lock entry. |
| `missing` | Tool cannot be resolved locally. |
| `unlocked` | Tool resolves, but the lock is missing or does not match `goark.build`. |
| `drift` | Declaration, metadata, or executable digest differs from the lock. |
| `error` | Build digest or another status check failed. |

`tools` is read-only and never installs.

## Explicit Installation and Verification

```bash
goark tool install goark-orm
goark tool verify
```

`tool install <name>` forces installation/resolution of the selected declared tool, updates only its current-platform lock entry, and refreshes trust. `tool verify` verifies every declared tool without installation or writes.

## Go Tool Cache

Go tools are installed below the OS user cache directory under `goark/tools/go/<key>/bin`. The key includes package, exact version, GOOS, and GOARCH. Installation uses a temporary directory, a per-tool cross-process lock, and atomic publication. The project's global `GOBIN` is not changed.

## Task Cache

Task cache manifests live under:

```text
.goark/cache/tasks/<task>/<fingerprint>.json
```

Caching is opt-in:

```toml
[tasks.generate-schema]
type = "go"
args = ["run", "./cmd/schema"]
inputs = ["schema/**/*.json", "cmd/schema/**/*.go"]
outputs = ["internal/schema/schema_gen.go"]
environment-inputs = ["SCHEMA_MODE"]
cache = true
```

A fingerprint includes:

- Normalized task name and definition.
- Input paths, modes, and content SHA-256 values.
- Locked tool entry, when applicable.
- Go version, GOOS, GOARCH, and build tags.
- Selected build Profile.
- SHA-256 of declared environment input values, never their plaintext.
- Upstream dependency output digests or skipped state.

A hit is accepted only when every declared output exists and its current path, mode, and content digest exactly match the manifest. Corrupt cache manifests are treated as misses. Cache manifests are atomically written.

## Cache Design Rules

- `cache = true` requires non-empty `inputs` and `outputs`.
- Declare every file and environment value that can affect output.
- Do not cache network-, clock-, or machine-dependent work unless those dependencies are converted into explicit inputs.
- Avoid overlapping outputs; the task graph rejects potential conflicts before execution.
- Cache does not restore deleted output files. Missing or changed outputs cause a miss and rerun the task.

## Cleanup

Preview and remove declared command outputs, task outputs, and the project task cache:

```bash
goark clean --goark-dry-run
goark clean
```

`clean` does not remove the user Go tool cache, lock file, or trust records.
