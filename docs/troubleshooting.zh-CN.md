# 故障排查

[English](troubleshooting.md) | 简体中文

## 找不到 `goark.build`

项目感知命令会定位 `go.mod`，并要求同级存在 `goark.build`。请在目标模块内运行，支持时使用 Go 的 `-C` 参数，或者在 `go.mod` 同级创建该文件。`goark go ...`、`new`、`codegen`、`help`、`version`、`completion` 不需要它。

## TOML 未知字段或重复字段

解析器是严格模式。根据 [`goark.build` 参考](goark-build.zh-CN.md)检查拼写和 table 位置，不要保留废弃或尚未实现的字段。同一个 key 只能声明一次。

## 编码或换行失败

`goark.build` 和 `goark.build.lock` 必须使用 UTF-8 无 BOM 和仅 LF。应配置 Git：

```gitattributes
*.build text eol=lf
*.lock text eol=lf
```

不要把这些文件转换为 Windows CRLF。

## 存在多个 main package

显式设置默认入口或在命令中传目标：

```toml
[project]
main = "./cmd/server"
```

```bash
goark run ./cmd/worker
goark build ./cmd/server
```

## 锁文件缺失或过期

有意修改构建或工具配置后：

```bash
goark sync
goark tool verify
```

检查并提交 `goark.build.lock`，不要手工修改构建摘要或可执行哈希。

## 工具缺失

- `install = "auto"` 的 Go 工具：联网运行 `goark sync`。
- `install = "manual"` 的 Go 工具：运行 `goark tool install <name>`。
- 系统工具：使用操作系统包管理器安装，并确保位于最终 `PATH`。
- 本地工具：在声明的项目路径构建或恢复可执行文件。

使用 `goark tools --json` 和 `goark doctor` 区分 `missing`、`unlocked`、`drift`。

## 项目不受信任

同步把信任绑定到规范化根目录和当前构建摘要前，Goark 会阻止自动恢复 Go 工具：

```bash
goark sync
```

移动项目或编辑 `goark.build` 后需要重新同步。

## 离线模式失败

离线执行不能安装或恢复工具。联网时先运行 `goark sync` 和 `goark tool verify`，并确保 Go module cache 已包含全部依赖。`--goark-offline` 控制 Goark 工具安装；如果整个构建都必须断网，还需单独配置官方 Go，例如 `GOPROXY=off`。

## 任务循环或依赖缺失

依赖必须指向上游。不要让任务互相依赖，应抽取共享前置任务来打破循环。修复名称后检查：

```bash
goark graph
goark graph --format=dot > tasks.dot
```

## 输出冲突

每个任务必须拥有互不相交的输出集合。应分配独立目录或精确文件。`build/**` 这类宽泛模式会与嵌套输出冲突，只能由一个任务拥有。

## 缓存始终未命中

检查输入是否稳定、任务成功后每个输出模式是否匹配、输出字节和权限是否不变，以及所有影响输出的环境值是否列入 `environment-inputs`。Profile、Go 版本、GOOS/GOARCH、构建标签、工具锁和上游输出变化也会让缓存失效。

删除缓存前先运行 `goark clean --goark-dry-run`。

## 生成文件未被覆盖

Goark 只替换带有以下标头的目标：

```go
// Code generated by goark; DO NOT EDIT.
```

同名手写文件会按设计阻止生成。应重命名手写文件，或者有意替换为 Goark 所有的生成文件。不要给人工维护代码添加所有权标头。

## 标准 `go generate` 没有执行

这是预期行为。`goark generate` 只负责 Goark 编译期生成：

```bash
goark go generate ./...
```

## Profile 对运行期没有作用

`--goark-profile` 只选择构建 Profile。Boot 运行期 Profile 需要单独激活：

```bash
goark run --goark-profile=dev --goark.profiles.active=dev
```

也可以设置 `GOARK_PROFILES_ACTIVE=dev`。

## 无修改诊断

```bash
goark info
goark info --json
goark tools --json
goark graph --format=json
goark build --goark-dry-run
```

`doctor` 同样不修改项目状态，但会探测已安装的 Go 可执行文件。
